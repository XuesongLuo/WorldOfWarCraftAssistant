# 2026-10-01 已开发实现迁移清单

## 目的

依据 ADR-016，把项目从“插件面板是聊天入口和定位前提”迁移到“Windows 覆盖层独立可用、插件只提供可选公开上下文”。本清单记录已开发内容的保留、修改和删除结论，并作为后续 STEP-008、STEP-012 与 STEP-018 的实现边界。

## 已保留

| 内容 | 结论 | 原因 |
|---|---|---|
| Win32 单实例、COM、托盘和资源 RAII | 原样保留 | 与产品入口变化无冲突 |
| WoW 进程/窗口发现和多客户端显式选择 | 保留 | 覆盖层和捕获仍需选定窗口 |
| 稳定身份选择持久化 | 保留 | 不包含角色私密身份，避免每次重新选择 |
| 客户区只读捕获 PoC | 暂时保留 | 用于锚点与迁移测试；STEP-012 改为 Windows Graphics Capture |
| 双锚点图像识别算法和夹具 | 保留为可选能力 | 可提高插件数据桥区域定位精度，但不决定核心可用性 |
| 手动矩形校准数学与测试 | 保留并改名义 | 从“插件内容区回退”改成“覆盖层/观察区域校准” |
| C++/TypeScript JSONL、严格字段校验和顺序跟踪 | 保留并升级 | 安全边界仍适用，活动协议升级到 v2 |
| 插件设置持久化、拖动缩放、错误隔离 | 保留 | 继续服务上下文卡片和数据桥 |

## 已修改

| 内容 | 修改结果 |
|---|---|
| Companion 生命周期 | 删除 `waiting_for_addon_panel`；选中 WoW 后直接 `ready` |
| 锚点检测失败 | 从恢复性错误改成可选能力不可用提示，核心覆盖层继续工作 |
| 手动校准文字与菜单 | 改为覆盖层区域，不再要求插件面板 |
| 插件 UI | 改成公开字段预览、协议/帧状态和数据桥开关 |
| 插件上下文 | 移除 Companion 在线假设；只输出通过类型和 secret-value 检查的公开字段 |
| 插件发布机制 | 默认关闭、事件驱动、100 ms 合并、512 字节上限、持续可见、单向无返回通道 |
| 活动跨进程协议 | 升级到 v2；加入 `coach`、来源、时间、置信度、隐私边界和回复 provenance |
| WebView2 环境 | SDK 固定版本/哈希，Runtime 采用 Evergreen 检测策略 |
| STEP-007 门禁 | 窗口发现是核心；锚点验证只阻塞增强路径 |

## 已删除

| 内容 | 删除原因 |
|---|---|
| 插件聊天输入框和发送按钮 | WoW 插件不能承担与本地 AI 的实时聊天 |
| 插件“伴侣程序离线/在线”状态 | 插件没有可靠实时 IPC，显示该状态会误导用户 |
| Companion 等待插件面板状态 | 违反无插件可用要求 |
| 锚点缺失即进入错误状态 | 插件只是可选增强，不能成为核心启动门槛 |

## 后续尚未完成

1. STEP-008 实现真正的透明、可交互 WebView2 Composition 覆盖层，并验证焦点、DPI、多屏和自动隐藏。
2. STEP-012 将 GDI 捕获迁移到 Windows Graphics Capture，增加前台门控、原始帧不落盘和观察会话状态。
3. STEP-018 对技能、天赋、动作条、成就和物品等字段逐项完成 API 来源与 secret-value 审计后加入数据桥。
4. 为插件像素帧实现 C++ 解码器、CRC/序号/频率验证和跨缩放测试；当前只完成插件发布端骨架。
5. 在正式服重新执行新的插件数据桥人工测试；旧 STEP-005 结果只作历史证据。
