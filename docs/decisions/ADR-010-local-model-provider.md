# ADR-010：M0 默认本地模型提供方

- 状态：已接受（2026-10-02）
- 日期：2026-09-28
- 负责人：项目负责人（选择）/ AI 运行时技术负责人（验证）
- 决策截止点：STEP-011 开始前
- 关联：E-10、E-11、E-13、E-14、E-18

## 背景

M0 必须在断开外网时跑通纯文本对话，并为截图能力探测保留接口。Ollama 和 LM Studio 的安装、API 兼容性、模型分发和视觉支持不同。

## 决策

M0 使用 Ollama 作为默认且唯一实现的本地提供方：只连接玩家显式配置的、无凭据的 HTTP
loopback origin，不自动安装模型、不静默拉取模型、不回退云端。Host 通过 Ollama 的版本、
模型列表与模型详情接口确认连通性、精确模型名及文本/视觉/工具能力，再将锁定 Codex App
Server 配置为 Responses API 客户端。LM Studio 复用同一提供方接口，最迟在 STEP-021 补齐。

当前实现与自动失败路径已验证；接受本 ADR 表示提供方选择和安全边界已确定，不代表真实模型
离线验收已完成。开发机尚未安装 Ollama。2026-10-02 项目负责人明确决定跳过本阶段真实模型
验收并推进 STEP-012；该门禁保持未通过并延期至 STEP-021，不得解释为能力已被验证。

## 验证与接受条件

- 显式配置端点和模型，验证 loopback 限制、超时、错误响应与能力探测。
- 断开外网仍可完成文本对话。
- 模型不支持视觉时只保留文字问题并明确提示。
- 未运行、模型缺失和响应畸形均有可操作错误，不触发自动下载。

## 回退方案

若 Ollama 无法满足 Windows 分发或所选模型能力要求，切换到 LM Studio；若两者均不可用，M0 保留确定性模型模拟器并阻断 STEP-013 放行，不静默启用云端。

## 依据

- OpenAI Codex 配置参考：自定义 `model_providers` 可固定 `base_url`、Responses API、认证与重试策略。
- Ollama Codex 集成文档：本地 `/v1/` Responses API 可作为 Codex 自定义提供方。
- Ollama API 定义：`/api/version`、`/api/tags`、`/api/show` 提供版本、已安装模型与能力信息。
