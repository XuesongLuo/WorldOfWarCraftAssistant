# ADR-002：浮层定位方案

- 状态：PoC 已实现，等待正式服验证
- 日期：2026-09-28
- 负责人：Windows 客户端技术负责人
- 决策截止点：STEP-007 完成前
- 关联：G-01、G-02、G-07

## 背景

伴侣程序必须在不读取 WoW 进程内存、不注入、不模拟输入的前提下，把浮层对齐到插件面板。窗口标题不稳定，UI 缩放、DPI、多显示器和多个客户端都会影响坐标。

## 默认 PoC 假设

采用混合方案：先由玩家明确选择 WoW 窗口，再从只读屏幕图像中识别插件提供的高对比度视觉锚点；识别失败时进入手动校准。保存的是窗口稳定标识和相对布局参数，不保存屏幕图像。

## 候选方案

1. 仅图像锚点：自动化程度高，但易受 UI 缩放和主题影响。
2. 仅手动绑定：实现简单，但首次使用和窗口变化体验较差。
3. 混合方案（默认）：自动识别为主，手动校准为安全回退。

## STEP-007 实现结论

实现采用混合方案。窗口发现以受支持的可执行文件名和进程信息为主，标题只用于玩家选择时的
显示标签。插件提供左上角、右下角两个不同排列的可见色块锚点，使调整尺寸后的内容矩形可以
由两点直接计算。低置信度、缺失或重复锚点均不返回矩形；自动检测失败时只允许玩家对已选择
的 WoW 客户区执行两点手动校准。稳定选择仅保存可执行文件名、窗口类和安装路径的非明文
FNV-1a 指纹，不保存原始安装路径或画面。

合成 1080p、1440p、4K 矩阵已经通过；ADR 在正式服多 DPI、多尺寸和多客户端验收完成前不
转为“已接受”。

## 验证与接受条件

- 1080p、1440p、4K 及常见 DPI 下均有样本。
- 多个 WoW 窗口时不自动选择；锚点置信度不足时隐藏浮层。
- 识别失败不得扩大到全桌面捕获，不得遮挡未知区域。

## 回退方案

停用自动锚点识别，只保留玩家选择窗口后的手动校准；任何不确定状态默认隐藏浮层。
