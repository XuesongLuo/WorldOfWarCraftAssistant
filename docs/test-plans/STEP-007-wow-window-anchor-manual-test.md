# STEP-007 WoW 窗口与锚点正式服人工测试

> 当前定位：窗口发现与多客户端选择属于核心路径；插件锚点只验证可选增强路径。锚点人工验收失败不得阻塞无插件覆盖层进入 Ready。

## 目的

在不读取进程内存、不注入、不模拟输入且不保存玩家截图的前提下，验证伴侣程序可发现正式服
窗口、在多客户端场景下要求玩家选择，并通过两个可见锚点计算插件内容矩形。

## 环境记录

- 测试日期：2026.9.30
- Windows 版本：win11
- WoW 区域、版本与 build：12.1.0 / build 69933 / Sep 18 2026 / Interface 120100
- 插件提交：待填写
- 伴侣程序提交：待填写
- 显示器/DPI：显示器 2560×1440；WoW 渲染区域 2560×1369（100%）
- 分辨率与 WoW 显示模式：窗口模式

不得把游戏截图、角色名、战网身份或安装路径提交到仓库。只记录下表中的成功率、坐标误差和
错误结论。

## PoC 门槛

- 1080p、1440p、4K 各至少一个场景，每个场景连续刷新三次，双锚点识别成功率为 100%。
- 至少覆盖插件缩放 75%、100%、135%，以及默认尺寸、最小尺寸、最大尺寸。
- 合成矩阵的内容矩形边缘误差为 0；正式服画面人工核对误差不超过 3 个物理像素。
- 两个同类客户端存在且稳定标识不能唯一匹配时，必须要求玩家手动选择。
- 锚点缺失、重复、窗口最小化或捕获失败时不得产生内容矩形。

## 用例

| 编号 | 操作 | 预期结果 | 实际结果 |
|---|---|---|---|
| M-001 | 不启动 WoW，启动伴侣程序 | 显示 `WaitingForWow`，提示未发现窗口，不报致命错误 | 已验证通过 |
| M-002 | 启动一个正式服窗口，从托盘刷新 | 通过 `Wow.exe` 进程信息发现并选择；不依赖窗口标题 | 已验证通过 |
| M-003 | 同时启动两个正式服窗口，选择 `Forget saved WoW selection` 后刷新 | 不自动猜测；托盘列出 PID，要求玩家明确选择 | 已验证通过 |
| M-004 | 选择其中一个窗口并重启伴侣程序 | 保存的非识别性稳定标识可唯一匹配时恢复；匹配仍歧义时再次要求选择 | 待验证 |
| M-005 | 1080p、插件 100%、默认尺寸，打开 `/wowai` 后连续刷新三次 | 三次均进入 `Ready`，显示内容矩形，误差 ≤3 px | 待验证 |
| M-006 | 1440p、插件 75%、最小尺寸，连续刷新三次 | 三次均识别双锚点，内容矩形随尺寸变化，误差 ≤3 px | 待验证 |
| M-007 | 4K、插件 135%、最大尺寸，连续刷新三次 | 三次均识别双锚点，内容矩形随尺寸变化，误差 ≤3 px | 待验证 |
| M-008 | 关闭 `/wowai` 面板后刷新 | 进入可恢复错误，不生成或沿用未知内容矩形 | 待验证 |
| M-009 | 最小化所选 WoW 后刷新 | 捕获失败并给出恢复建议，不扩大到桌面捕获 | 待验证 |
| M-010 | 自动识别失败后，从托盘执行 Manual calibration，再 Reset calibration | 两点校准可建立临时内容矩形；重置后重新执行自动检测 | 待验证 |
