## 2026-09-30 人工初测反馈与修复

M-001～M-003、M-006～M-010 通过。初测发现并修复：

- M-004：拖动区域由整个面板收窄为标题栏，自动门禁禁止重新注册整个面板。
- M-005：缩放和关闭控件改用 WoW 原生 `UIPanelButtonTemplate`，减号改用 ASCII 字符。
- M-011：离线提示区增加固定高度，并增大与输入区的垂直间距。

修复后的插件静态门禁、仓库验证及 `git diff --check` 通过。M-004、M-005、M-011
仍需在正式服复测；环境记录仍需补全。

第二轮正式服复测确认上述三项缺陷已解决。根据 M-005 的追加体验反馈，缩放逻辑进一步
调整为先把面板重锚定到右上角控制区、再改变缩放并保存锚点，使原位置的缩放按钮保持在
鼠标附近。曾误解为移动控件，已撤销该布局改动。此调整需最终复测 M-005。

右上角锚点方案在正式服复测中仍有按钮位移。实现已改为记录本次实际点击按钮的中心坐标，
缩放后再次测量并用坐标差反向平移面板，因此不再依赖控件相对右边缘的缩放偏移假设。

坐标补偿方案在正式服复测中仍未改变实际表现，因此已撤销。缩放按钮、百分比和关闭按钮
现放入调用 `SetIgnoreParentScale(true)` 的独立控制层：主面板缩放时控制层不参与父级缩放，
从结构上消除按钮随面板比例改变而移动的问题。该能力存在于正式服 12.1.0 Frame API。

独立控制层导致按钮不随面板改变大小并出现视觉错位，且固定按钮位置不再作为目标。根据
最终反馈已撤销独立层：控制按钮重新作为面板普通子元素参与等比例缩放；缩放前将面板当前
中心规范化为 `CENTER` 锚点，使宽高变化围绕面板中心向四周展开。

按钮等比例缩放在正式服复测中通过，但缩小时面板向左下、放大时向右上移动。原因是
`GetCenter()` 的面板有效缩放坐标被直接作为 `UIParent` 偏移使用。中心锚点现先乘以
`frame:GetEffectiveScale()`、再除以 `UIParent:GetEffectiveScale()`，转换到父级坐标后才缩放。

上述换算仍在正式服产生相同或更严重的漂移，原因是锚点在改变比例之前设置，随后锚点偏移
再次受新比例影响。实现已更正顺序：先以旧有效缩放保存中心的物理屏幕位置，设置新比例，
最后除以新有效缩放反算 `CENTER` 锚点，从而保持缩放前后的物理中心一致。
